# Perfil RH + Atendimento para o funcionário (22/10/2026)

## Pedido
1. Reativar as funções de RH escondidas no menu.
2. Criar um perfil de RH "somente com as informações relevantes".
3. Fazer o Atendimento aparecer para o funcionário abrir ticket.

## Decisões
- Novo perfil `RH` (valor no banco: `RH`), independente de Gerente.
- `ehRH` no backend passou a valer para `rh`, `gerente` e `administrador`.
- Telas do RH: Início, ASO, Banco de Horas, Folgas, Atendimento, Comunicados,
  Notificações + MIPs e Reclamações **somente leitura**.
- Fora do RH: Receitas, Avaliações, Meu desempenho, Usuários e Configurações
  (bloqueados também na API, não só no menu).
- RH usa as telas de gestão (sem visão "meus dados").
- RH só é criado por Administrador: Usuários → perfil "RH" ou planilha
  (`Funcionario, Lider, Gerente, RH, Administrador`).
- Atendimento: item novo na topbar do funcionário e atalho no Início.

## Implementação
- `backend/index.js`: `PERFIS_RH`/`ehRH`, bloqueio de `/api/receitas` e
  `/api/avaliacoes` no `verificarToken`, MIPs read-only para `rh`,
  `podeVerReclamacoes` (RH lê mas não registra/edita), destinatários de
  notificação, criação/edição/importação de usuários com perfil `rh`.
- `frontend/src/`: `Dashboard` (ATALHOS_RH), `Sidebar` (oculta Receitas e
  Avaliações para `rh`), `App.jsx` (rotas restritas), `Usuarios.jsx`,
  `Reclamacoes.jsx` (lista em modo leitura), `LeitorTopbar.jsx` (Atendimento).
- Versão 2.12.0.

## Ajuste (mesmo dia)
- Notificações operacionais do RH (ticket novo/mensagem, folga solicitada,
  ASO vencido/confirmado) agora vão **somente para o perfil RH**
  (`SQL_DESTINATARIOS_RH` no backend). Gerente e Administrador não recebem mais.
- Nova reclamação notifica líder responsável + **Gerentes + Administradores**
  + Ximene (nutri). O aviso de MIP em revisão continua exclusivo do
  Administrador, que é quem aprova.
- Avisos de avaliação continuam indo apenas para o avaliado.
- Atenção: enquanto não existir usuário com perfil RH, ticket/folga/ASO não
  geram notificação para ninguém.
